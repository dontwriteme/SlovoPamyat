## Какую версию читать

- Аудит относится к опубликованной ветке `work` на коммите `5baddb92e9240998e5033de4462a48812d0d395c`. Это Android-приложение версии 0.21.6 с Java и SQLite v9. [Проверенная версия на GitHub](https://github.com/dontwriteme/SlovoPamyat/tree/5baddb92e9240998e5033de4462a48812d0d395c)
- Изначально документы подготовлены в локальном черновике ветки `work` на `9683baa6ad6db990f96307fc43e7bd98060adbd0`. На момент сверки удалённая ветка содержала 65 последующих коммитов. Показатели для черновика и опубликованной ревизии приведены раздельно. Ветка R0 основана на проверенной опубликованной ревизии и включает исходный коммит документации.

## Что требует внимания

**P0 — 0, P1 — 2, P2 — 12, P3 — 4.** Наибольший риск связан с частичной записью неверного ответа ([A02](AUDIT.md#a02), воспроизведено) и порядком фиксации данных при восстановлении копии ([A01](AUDIT.md#a01), подтверждён по коду, возможное смешанное состояние ещё предстоит воспроизвести). Четыре исходных сбоя контрольной JVM-регрессии устранены в R0 ([A06](AUDIT.md#a06)).

**Следующий рекомендуемый шаг** — согласовать R1 и защитить транзакцию записи ответа A02. Устойчивость восстановления A01 вынесена в R2. [Порядок работ](ROADMAP.md)

## Как поддерживать документы

После каждого согласованного этапа добавляйте запись в [PROGRESS.md](PROGRESS.md) с затронутыми ID, коммитом, результатами и ограничениями. Меняйте статус в [AUDIT.md](AUDIT.md) по конкретному доказательству. Новые замеры и проверки добавляйте в соответствующий отчёт с ревизией и условиями прогона. Согласованные решения фиксируйте в [DECISIONS.md](DECISIONS.md), а изменение порядка работ — в [ROADMAP.md](ROADMAP.md). При новом выводе сохраняйте связь с исходным ID.
