## R2 · Восстановление резервной копии

**Итог на `ed192aa`.** Полная JVM-регрессия — 152/152 (21 набор, 0 пропусков), включая R0 и R1. Собран стандартный `org.biblememory.app` версии 0.21.6, подпись APK v2 проверена. Для устройства отдельно собраны APK приложения и instrumentation с изолированным ID. Адресно прошли 12 JVM-тестов резервных копий и миграций и два теста запоздавших операций. Команда полного прогона — `gradle --daemon --max-workers=4 -I tests/validation.init.gradle -x :app:createSynodalSearchIndex :app:testDebugUnitTest :app:assembleDebug`.

**Исходный дефект.** На опубликованном R1 экспортировали тестовую коллекцию, поставили в текущей БД вторую коллекцию и заменили маркер черновика. `ContextWrapper` прерывал импорт через `AssertionError` при втором обращении к `collection_study_queue` (после записи первой группы настроек). Транзакция откатилась. В базе осталось две коллекции, а в `study_session` появился маркер из импортируемой копии. Эту JVM-пробу выполняли отдельно от испытаний с уничтожением процесса.

## R0 · Стабилизация контрольного тестирования

| Сценарий | Первопричина и исправление |
| --- | --- |
| `nonemptyNoMatchKeepsQueryUntilClear` | Ошибка теста. Обход View выполнялся сразу после создания ListView. Поисковый EditText в header становится дочерней View после layout. Теперь тест вводит запрос в настоящее поле, пропускает виртуальные часы debounce, выполняет поиск, ждёт layout и проверяет сохранение запроса и результат очистки. |
| `clearingVirtualResultsPreservesCatalogScroll` | Ошибка теста. Тот же ранний обход header и искусственно заполненный `savedScrollY`. Теперь проверяется сохранение фактической прокрутки 123, виртуализация результата, очистка через EditText и восстановление положения на экране. |
| `ordinaryReaderUsesAll176VerseNumbersAndBackStack` | Ошибка подготовки Activity в тесте. Layout страницы моделировался до подключения видимого окна, поэтому отложенный переход не отрабатывал. Тест теперь показывает Activity, проверяет все 176 номеров, видимость карточки стиха 176, исчезновение подсветки и весь стек возврата. |
| `overlapDuplicateAndDeletedCollection` | Конкуренция записи с фоновой транзакцией. В предыдущем полном прогоне прямое удаление на UI-helper завершилось SQLITE_BUSY, пока экран коллекции использовал другой helper. В R0 UI-удаление ставится в очередь с чтениями и изменениями коллекций. Тест удерживает транзакцию на worker во время подтверждения удаления, затем проверяет исчезновение коллекции, отказ повторного добавления и сохранение записей. |

Первый адресный прогон на `5baddb9` воспроизвёл две ошибки EditText и ошибку прокрутки. Четвёртый сценарий прошёл в этом запуске. Его сбой взят из воспроизведения полного прогона аудита. Новая проверка управляет перекрытием операций с помощью latch, поэтому ей не нужно случайное совпадение потоков.

**SQLite и границы тестов.** В исходном стеке SIGSEGV участвовали `Finalizer → SQLiteConnection.finalize → ShadowNativeSQLiteConnection.nativeFinalizeStatement → sqlite3_finalize`. SQLITE_BUSY возникает на отдельном пути Legacy sqlite4java при выполнении DELETE. Общая первопричина не доказана. Загрузчик Библии ранее мог обращаться к UI-helper параллельно с его закрытием. Теперь синхронизация коллекций выполняется через helper существующего worker. Закрытие остаётся в очереди за работой, а поздний callback не обновляет уничтоженную Activity. Интеграционные тесты ожидают завершения обоих executor перед сбросом Robolectric. Отдельная регрессия удерживает работу при уничтожении Activity, проверяет открытое соединение во время работы, его закрытие после выхода и отсутствие поздней перерисовки. Конфигурация режимов NATIVE/LEGACY сохранена, постоянная изоляция JVM и автоматические повторы не вводились.

## Выполненные проверки и известные ошибки

Для опубликованной версии:

- **Gradle 8.9, JDK 17, SDK 35.** `:app:assembleDebug` собрал APK, его подпись v2 прошла `apksigner verify --verbose`. Общая задача `assembleDebug + testDebugUnitTest + lintDebug` завершилась с ошибками тестов и Lint.
- **Полная JVM-регрессия.** При обычном запуске 130 начатых тестов, 4 ошибки, 1 пропуск в неполном результате перед SIGSEGV. Диагностический повтор с теми же тестами и отдельной JVM на класс: **135 тестов, 131 прошёл, 4 упали, 0 пропущено**. Все ошибки в `PickerIntegrationTest`: `nonemptyNoMatchKeepsQueryUntilClear` и `clearingVirtualResultsPreservesCatalogScroll` (нет EditText), `ordinaryReaderUsesAll176VerseNumbersAndBackStack` (нет ожидаемой прокрутки), `overlapDuplicateAndDeletedCollection` (SQLITE_BUSY на удалении). Миграции (2), полный бэкап (2), долговечность прогресса (3), жизненный цикл сессий (9), снимок прогресса (8), орфография (8) и тесты хотбара/упражнений (15 интеграционных) прошли. Пять отдельных диагностических проб выполнены на каждой ревизии, ещё одна проба отказа SQLite выполнена на публикации. Часть проб собирает метрики и состоявшиеся эффекты, поэтому их зелёный статус не означает отсутствия дефектов. [Результаты из XML](evidence/TEST_RESULTS.csv)

Этот runner проверяет открытие текста, но не величину прокрутки на стих и не ввод в поиск. Четыре ошибки JVM остаются в реестре. Реальные FPS, Android API 26 и принудительное уничтожение процесса после восстановления не проверены. [Вывод прогона](evidence/ANDROID_API28.txt)

Поисковый индекс пересоздан в отдельном снимке: 31 169 стихов, 33 055 терминов, SHA-256 исходного JSON и индекса совпали с исходными.
- **Черновик для сравнения.** 105 тестов, 102 прошли, 3 ошибки в тех же сценариях поиска и прокрутки. APK собрался. Lint показал ту же ошибку API 26. Отсутствие SQLITE_BUSY в этом прогоне не показывает частоту ошибки.

## Воспроизведение исходных проверок

Команды для отдельной копии выбранной ревизии с настроенными Gradle 8.9, JDK 17 и SDK 35. `audit_dir` указывает на абсолютный путь к каталогу `docs/audit` с этим отчётом. Тестовые SQLite-данные создаются Robolectric. Внешние диагностические тесты прикрепляются через init-скрипт, без изменений исходных файлов приложения. [Исходник проб](evidence/repro/AuditProbe.java) · [Init для проб](evidence/repro/probes.init.gradle) · [Init раздельного прогона](evidence/repro/isolate.init.gradle)

```bash
gradle --daemon --max-workers=4 --continue -I tests/validation.init.gradle \
  -x :app:createSynodalSearchIndex :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
gradle --daemon --max-workers=4 -I tests/validation.init.gradle \
  -I "$audit_dir/evidence/repro/isolate.init.gradle" -x :app:createSynodalSearchIndex :app:testDebugUnitTest
gradle --daemon --max-workers=4 -I tests/validation.init.gradle \
  -I "$audit_dir/evidence/repro/probes.init.gradle" -PauditProbeDir="$audit_dir/evidence/repro" \
  -x :app:createSynodalSearchIndex :app:testDebugUnitTest --tests '*AuditProbe*'
python3 tests/check_bible_grids.py
python3 tests/audit_inline_gaps.py
python3 tests/audit_orthography.py
```

Тест `failedReviewPartiallyCommitsOnSqliteError` характеризует дефект публикации A02. Остальные пять тестов формируют базовые данные на обеих ревизиях. Аудит пропусков обновляет отчёт TSV, а генератор поискового индекса пишет бинарный файл, поэтому оба запускались на отдельном снимке.
