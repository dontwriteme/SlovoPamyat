## R4.2 · Загрузка корпуса (A04)

JDK 17, Robolectric API 28, один JVM-прогон каждой пробы на каждой ревизии. Разбор замерен на 12 изолированных экземплярах `Bible`. Значение включает чтение ресурса, JSON и подготовку данных. Первый вызов включён в медиану. Для проверки ожидания слой чтения ресурса удерживал загрузчик примерно 100 мс, пока основной поток вызывал `isReady()`. Этот тест отделяет блокировку проверки от обычного замера запуска.

| Показатель | R4.1 | R4.2 |
| --- | ---: | ---: |
| Медиана загрузки, 12 разборов | 165,672 мс | 99,115 мс |
| Один вызов `isReady()` при задержке, основной поток | 183,305 мс, вернул готовность после разбора | 0,012 мс, сразу вернул состояние ожидания |
| Разборы при запуске → входе в Библию → повторении через стандартный helper → пересоздании | 1 + 0 + 1 + 1 | 1 + 0 + 0 + 0 |

Счёт получен в отдельных тестовых копиях с одной строкой трассировки в начале фактического разбора. В R4.1 повторение через отдельный стандартный helper запустило разбор на главном потоке. Повторение через уже готовую Activity дополнительного разбора не требовало. В R4.2 обращение через новый стандартный helper также использует общий снимок. При открытии вкладки во время разбора тест Activity видит экран загрузки, а замена Activity не дожидается окончания разбора.

Медианы двух прогонов характеризуют стенд, хотя алгоритм разбора оставлен прежним. Кадры и время первого кадра, память, эмулятор и физическое устройство не измерялись. [Проба времени](evidence/repro/BibleLoadProbe.java) · [Проба числа разборов](evidence/repro/R42ProcessProbe.java)

Пробы запускаются с `-I tests/validation.init.gradle -I docs/audit/evidence/repro/bible-loading.init.gradle -x :app:createSynodalSearchIndex :app:testDebugUnitTest --tests '*BibleLoadProbe' --tests '*R42ProcessProbe'`. Для счётчика в отдельной копии добавляется `System.out.println("R42 parse " + Thread.currentThread().getName());` перед первым чтением JSON. Исходная ревизия R4.1 — `0e4ba5d592ff2afa1e1dc3bfc573581535191ea5`. Вывод доступен в тестовых XML.

## R4.1 · Прогресс главы (A05)

Измерен только `LocalStore.statusesForChapter` на JVM с JDK 17, Robolectric API 28 и SQLite NATIVE. База содержит 149 стихов Галатам. Большой набор дополняет её Псалтирью 1–40 и 118 до 962 стихов. У каждого стиха один срок и три строки истории, одна из них с неточным ответом. В каждой строке таблицы по 30 вызовов до и после, после четырёх прогревочных. Холодный означает новый SQLite-helper с открытой базой и пустым снимком. Повторный использует тот же helper и неизменную базу. Открытие SQLite, загрузка Библии и отрисовка сюда не входят. Считались вызовы `readQuery`. Медиана — среднее двух центральных наблюдений, p95 — 29-е наблюдение из 30 по возрастанию. [Проба](evidence/repro/ChapterStatusProbe.java)

| База / глава | Вызов | Чтения R3 → R4.1 | Медиана R3 → R4.1, мс | p95 R3 → R4.1, мс |
| --- | --- | ---: | ---: | ---: |
| 149 / Галатам 1, 24 стиха | Холодный | 223 → 9 | 22,249 → 9,837 | 37,720 → 13,474 |
| 149 / Галатам 1, 24 стиха | Повторный | 217 → 3 | 11,265 → 1,932 | 14,677 → 4,015 |
| 962 / Галатам 1, 24 стиха | Холодный | 223 → 9 | 17,187 → 21,342 | 57,485 → 36,475 |
| 962 / Галатам 1, 24 стиха | Повторный | 217 → 3 | 7,994 → 4,877 | 9,964 → 6,251 |
| 962 / Псалтирь 118, 176 стихов | Холодный | 1591 → 9 | 42,595 → 14,488 | 67,613 → 21,415 |
| 962 / Псалтирь 118, 176 стихов | Повторный | 1585 → 3 | 37,903 → 6,899 | 59,412 → 7,908 |

На большой базе медиана холодного вызова для Галатам выросла на 4,155 мс. Во всех измеренных случаях снизилось число чтений, а повторные вызовы заняли меньше времени. Результаты характеризуют этот стенд. Память, время отрисовки, кадры, эмулятор и физическое устройство в R4.1 не измерялись.

Для воспроизведения на проверяемой версии запустите из корня репозитория с одной и той же пробой:

```bash
gradle --daemon --max-workers=4 -I tests/validation.init.gradle \
  -I docs/audit/evidence/repro/chapter-status.init.gradle -x :app:createSynodalSearchIndex \
  :app:testDebugUnitTest --tests '*ChapterStatusProbe'
```

Исходная ревизия R3 — `2e24ab5d0f58e9ab61da5c4a30205a6a27ec7fed`. Для замера R3 нужны два файла пробы из R4.1. Строки `CHAPTER` находятся в тестовом XML. [Конфигурация пробы](evidence/repro/chapter-status.init.gradle)

## R2 · Память резервной копии (A09)

Один адресный замер финальной версии сериализатора на эмуляторе API 28 x86_64. В отдельную базу записаны 32 синтетические карточки по 32 768 кириллических символов и черновик такого же размера. Распакованная оболочка заняла 2 169 633 байта, gzip — 5 255 байт. Размер gzip объясняется повторяющимися символами. Каждые 10 мс измерялось `Runtime.totalMemory() - freeMemory()`. Перед каждой операцией запрашивалась GC. [Сценарий profile](../../tests/device/org/biblememory/app/R2BackupCheck.java)

| Операция | Занято перед стартом, байт | Максимальное наблюдение, байт | Время на эмуляторе |
| --- | ---: | ---: | ---: |
| Экспорт | 1 433 088 | 20 264 408 | 2 563 мс |
| Импорт с журналом | 1 204 872 | 24 921 616 | 3 108 мс |

Отсчёты могут пропускать короткие пики и исключают нативную память SQLite. В более раннем прогоне R2 на том же сценарии наблюдались 25 925 464 и 34 454 904 байта соответственно. Это наблюдения, по которым нельзя оценить прирост скорости или гарантировать импорт архива размером 100 МиБ. Лимит относится к распакованной оболочке. Экспорт проверяет его после формирования JSON и массива байтов. Импорт ограничивает распаковку, затем материализует буфер, строки и дерево JSON. Предлагаемая отдельная задача по A09 — потоковая сериализация с тем же SHA-256 и контрольным архивом v1, затем испытания при небольшом лимите heap и при усечённом входе. Основной риск — несовместимость байтов тела, по которым проверяется хеш.

## Исходные замеры

Изолированная тестовая БД, один и тот же стенд JVM в этой среде, Robolectric API 28 с Native SQLite, JDK 17, одинаковый тест и viewport 411×730. Главная содержит одну запись «Галатам» из 149 стихов. Первое отображение в таблице выполнялось **после готовности Библии**. Замер включает вызов и синхронный layout в JVM, без отрисовки GPU и без настоящих кадров. Одно прохождение на ревизию, кроме множества нажатий в одном уроке. Счётчик считает вызовы `LocalStore.readQuery`. Он не считает SQLite-записи, прямые `rawQuery`, работу других helper или внутренние запросы SQLite. [Сырые значения CSV](evidence/BENCHMARKS.csv)

| Операция | Черновик | Публикация | Что подтверждено |
| --- | ---: | ---: | --- |
| Главная с 149 стихами, первый render + layout | 271 мс, 1 052 чтения | 109 мс, 10 чтений | Основной повторный расчёт уже устранён. |
| Та же главная, следующий render + layout | 169 мс, 1 046 чтений | 63 мс, 4 чтения | Повторный прогон переиспользует пакетный снимок. |
| Подготовка режима памяти для 149 стихов | 51,4 мс, 449 чтений | 1,2 мс, 2 чтения | Пакетный путь уже работает. |
| Прогресс главы Галатам 1, 24 стиха | 22,4 мс, 289 чтений | 76,6 мс, 193 чтения | По-прежнему запросы на позицию. Одно измерение времени не устанавливает регрессию. |
| Есфирь 8:9, открытие сборки с layout | 63,4 мс | 59,9 мс | Профиль первого отображения нужен на Android. |
| Есфирь 8:9, нажатия с layout, p50 / p95 / максимум | 4,18 / 7,40 / 12,36 мс | 3,02 / 9,27 / 11,00 мс | Различие p95 не позволяет заявить улучшение задержки для всех нажатий. |
| Есфирь 8:9, чтения на нажатие | 5 на каждом | 0 на обычном, 2 на завершении фрагмента | На обычном касании убрана работа SQLite. |

В Есфирь 8:9 проба прошла доступные варианты от начала этапа до его завершения: 12 фрагментов и 128 нажатий в черновике, 11 и 127 в публикации. Порядок разбивки мог меняться вместе с версией алгоритма и состоянием выбора масок, поэтому объёмы различаются. Путь нажатия в публикации `OnClick → обновление lessonUsedTiles / lessonPicked → renderLessonBuildSelection → запись при завершении фрагмента`. Смена варианта и фрагмента по-прежнему строит соответствующие View, первый расчёт ширины использует измерение текста и подбор размера группы. Наиболее полезные отдельные метрики на Android — время открыть экран, отклик на правильную/ошибочную плитку, окончание фрагмента, поворот с набранным префиксом, p95 кадров и аллокации. Целевые FPS, задержки конкретных телефонов и выигрыши в процентах из этих данных не следуют. [Реализация сборки](https://github.com/dontwriteme/SlovoPamyat/blob/5baddb92e9240998e5033de4462a48812d0d395c/app/src/main/java/org/biblememory/app/MainActivity.java#L6178-L6270)

## Что измерено и чего пока не хватает

| Область | Доказательство и пределы |
| --- | --- |
| Генерация упражнений | Есть время открытия сборки с layout и время подготовки режима памяти. Отдельное время токенизации, выбора масок и генерации плиток не выделялось. |
| Длинные отрывки | Есть проход Есфирь 8:9 и подготовка режима памяти для 149 стихов. Время проверки длинного письменного ответа, полный урок по главе и коллекции 500+ на Android не измерялись. |
| Главный поток | Зафиксированы синхронные чтения прогресса главы и общий монитор загрузки Библии. Длительность блокировки UI и кадры измерить ещё предстоит. [A04](AUDIT.md#a04) · [A05](AUDIT.md#a05) · [A11](AUDIT.md#a11) |
| Перерисовки | По коду обычное нажатие на плитку обновляет выбор локально. Смена фрагмента создаёт View, а общий `render` перестраивает корень. Трассировки redraw и пропусков кадров нет. [A14](AUDIT.md#a14) · [A17](AUDIT.md#a17) |
| Память | Пейзаж 1200×750 при RGBA занимает около 3,4 МиБ по расчёту. Пики PSS и heap, суммарная память bitmap и верхняя граница для бэкапа не измерялись. [A09](AUDIT.md#a09) · [A17](AUDIT.md#a17) |
| SQLite | В таблице есть подмножество чтений через `readQuery`. EXPLAIN подтвердил полный проход по таблице сроков и отдельную сортировку. Время конкуренции между helper не измерялось. [A10](AUDIT.md#a10) · [A12](AUDIT.md#a12) |
| Жизненный цикл и утечки | Код фоновой загрузки удерживает Activity до окончания работы и допускает поздний callback. Постоянная утечка, объём удерживаемой памяти и частота не установлены. [A04](AUDIT.md#a04) |
| Холодный запуск | Время до первого кадра и до готовности Библии не измерялось. Замер главной начинался после загрузки Библии. [A04](AUDIT.md#a04) |
