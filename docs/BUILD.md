# Сборка Светоча: зафиксированный корпус и инструментарий

## Обычная сборка

Требуются JDK 17, Android SDK platform 35 и build-tools 35.0.0. AGP 8.7.3, Gradle 8.9, minSdk 26 и targetSdk 34 сохранены. Используйте официальный wrapper из этого репозитория (`gradlew.bat` вместо `./gradlew` на Windows).

```sh
./gradlew :app:assembleDebug
./gradlew -I tests/validation.init.gradle :app:testDebugUnitTest
./gradlew :app:lintDebug
```

Первая сборка может потребовать загрузки Gradle, SDK и зависимостей. После их установки и заполнения кэша проверяйте чистую офлайн-сборку:

```sh
./gradlew --offline :app:clean :app:assembleDebug
./gradlew --offline :app:verifySynodalSearchIndex
```

Офлайн не означает, что на совершенно новом компьютере отсутствуют требования к SDK или кэшам. Debug-подпись зависит от локального ключа. Не гарантируется побайтовое совпадение целых APK на разных компьютерах.

## Происхождение и контроль корпуса

Утверждённые байты взяты из проверенной ревизии R6.1 `8a1e13d7c794c9395ce65be0f96dc3cb028ca686`. Исторический источник, указанный в старой сборке: https://github.com/midvash/bible-data/blob/main/versions/ru/synodal/synodal.json . Ревизия внешнего проекта, из которой первоначально взят этот текст, не установлена. За эталон принимается именно сохранённый в нашем Git корпус, а не сегодняшняя внешняя ветка.

| Файл | Размер (байты) | Контрольная сумма |
| --- | ---: | --- |
| `app/src/main/assets/synodal.json` | 8689198 | SHA-256 `553df7df63cff838fabac65b480aaf1a07ad59d536c14c140c93e1b29d801bb4` |
| `app/src/main/assets/synodal.json` | 8689198 | Git blob `3497553c1ebf617f0491035178aa28f79241b9a5` |
| `app/src/main/assets/synodal.sidx` | 7091256 | Git blob `806cc16621f67ae506063b38123bf48c7b611a96` |
| `app/src/main/assets/synodal.sidx` | 7091256 | SHA-256 `2e80ca4f77b36a14f509628d66df185454e6298e89eda5ceb3309c7de65e7259` |

Git blob — SHA-1 с заголовком Git, не SHA-256 файла. Корпус проверяется по SHA-256, индекс — по фиксированному Git blob и при отдельной проверке побайтно против регенерированного индекса. Указанные файлы не подвергаются нормализации переводов строк при checkout. Обычная сборка не скачивает Библию, не регенерирует и не заменяет утверждённые ресурсы. При отсутствии или повреждении данных она завершается с ошибкой.

Для восстановления одобренных байтов из конкретного коммита используйте git restore с указанием исходной ревизии (сначала сохраните свои изменения, если они нужны).

## Явное обновление корпуса (отдельное согласование)

1. Получить кандидат в отдельной рабочей копии из конкретного проверенного upstream-коммита. Записать точный источник, лицензию, Git SHA и SHA-256; сравнить все изменения координат и текста с утверждённым корпусом. Обновление может влиять на идентичность материала и восстановление прогресса; необходима проверка совместимости.
2. Только после согласования замены скопировать кандидат в `synodal.json` и обновить `corpusSha256` в `app/build.gradle`. Выполнить `./gradlew :app:createSynodalSearchIndex --rerun-tasks`. Результат находится в `app/build/synodal-verification/synodal.sidx`, исходный индекс не заменяется.
3. После проверки кандидата скопировать новый индекс в assets. Получить Git blob через `git hash-object app/src/main/assets/synodal.sidx` и SHA-256 обоих файлов (например, `sha256sum` или PowerShell Get-FileHash). Обновить константу `indexGitBlob`, таблицу выше и сведения о происхождении.
4. Запустить `./gradlew :app:verifySynodalSearchIndex`, проверки сеток, пропусков, орфографии и полную регрессию. Изменение корпуса, индекса, контрольных сумм и документации публиковать вместе в одной ревизии.

Не обновляйте контрольную сумму только для устранения ошибки сборки.

## Wrapper и CI

Официальный источник: Gradle `v8.9.0`, https://github.com/gradle/gradle/tree/v8.9.0/gradle/wrapper .
Контрольные суммы опубликованы на https://gradle.org/release-checksums/ .

- Gradle 8.9 bin: SHA-256 `d725d707bfabd4dfdc958c624003b3c80accc03f7037b5122c4b1d0ef15cecab`.
- Wrapper JAR: SHA-256 `498495120a03b9a6ab5d155f5de3c8f0d986a449153702fb80fc80e134484f17`.

CI проверяет wrapper, повторное создание индекса, Lint, полную JVM-регрессию и сборку. Сохраняются прежние события запуска workflow. Это фиксация ключевых входов сборки, не полная герметизация всех внешних зависимостей или гарантированная воспроизводимость подписи.
