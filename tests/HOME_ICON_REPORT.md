# Иконка «Главная»: рисунок, окно и дым

`HomeNavigationIcon.java` перерисован нативно по приложенному пользователем
рисунку: оливковая скруглённая крыша, кремовые стены, крест, арочное окно слева,
дверь справа, труба и небольшие кусты. Это программная миниатюра образца, а не
вставка непрозрачного изображения с фоном. Размер слота остаётся 27 × 27 dp.
Индикатор `#F7DED0`, подписи, размеры панели и соседние вкладки не менялись.

## Найденные причины и исправления

- Старый `motionEnabled()` требовал `animator_duration_scale >= 1`. При популярной
  настройке 0,5× он немедленно вызывал settle, полностью исключая дым. Теперь
  отключение (0) по-прежнему даёт конечное состояние, а положительные масштабы
  обрабатывает сам Android ValueAnimator.
- Старое окно имело размер всего 3,2 × 3,2 dp, обводку 1 dp и смешивало янтарь
  с цветом контура (`light * .86`). Новое арочное окно шириной 5,9 dp получает
  непрозрачную янтарную заливку с мягким градиентом `#FFE49B → #FFC94E` и отдельной
  коричневой рамой. Свет остаётся после завершения движения, повторный клик даёт
  локальное усиление яркости без погасания.
- Старый дым занимал узкую полосу над трубой, рисовался цветом контура с alpha
  не более 140; три длинных завитка стартовали с интервалом 110 мс и накладывались.
  Теперь над трубой зарезервирована область около 5 dp. Три отдельные S-образные
  линии стартуют через 210 мс, каждая живёт 440 мс, поднимается и растворяется.
  На прежнем светлом индикаторе используется тёмный шалфейный `#486C55`, а не
  предложенный светлый дым, который терялся бы на этом фоне.

Полный цикл 1050 мс; окно включается в 100–350 мс, первый дым — с 180 мс.
Повторный клик оставляет свет и даёт один завиток за 650 мс. Выход — гашение за
180 мс без нового дыма. Один аниматор, без очереди. Paint, Path и Shader
создаются один раз; геометрия не выделяет новые объекты на каждом кадре.
Координаты дыма вместе с обводкой остаются внутри исходного слота
(верхняя граница -12,8 при доступных -13,5). Глобальное clipping не менялось.

## Проверки

Debug APK, отдельный instrumentation APK и все JVM/Robolectric-тестовые классы
собраны. Подпись APK проверена. 12 независимых тестов модели/поиска прошли без
ошибок и пропусков; проверка реальных данных 66 книг проходит.
`git diff --check` проходит. `MainActivity.java`, `BookNavigationIcon.java`,
навигация Библии и данные не менялись.

Добавлен отдельный `tests/home-icon-device.init.gradle` и framework-only runner
`tests/device/org/biblememory/app/HomeIconCheck.java`. В производственный APK
runner не входит, внешние тестовые библиотеки ему не нужны. Из обычного JVM
source set папка device исключена в `validation.init.gradle`.

Команды для подключённого Android-устройства/эмулятора:

```sh
gradle --no-daemon --max-workers=4 -I tests/home-icon-device.init.gradle -x :app:createSynodalSearchIndex :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w org.biblememory.app.test/org.biblememory.app.HomeIconCheck
```

Runner выполняет настоящие нажатия вкладок и сохраняет скриншоты, а также
увеличенные нативные отрисовки самого View, в
`/sdcard/Android/data/org.biblememory.app/files/home-icon-check/`.
Промежуточные фазы аниматора фиксируются для детерминированной визуальной проверки.
На Android API 28 получены кадры раскрытого окна, дыма при переходе и повторном
клике, а также состояния после ухода. Кадры просмотрены: свет и дым различимы.
Проверены сохранение аниматора после подключения кэшированной страницы,
отсутствие очереди при 20 повторных кликах и освобождение при уходе. Финальный
runner также проходит переход Коллекции → Главная и вызовы обработчиков
pause/resume через Instrumentation. Проверка
выполнена при системном масштабе 0,5×, который раньше полностью отключал дым.

Первый прогон был затруднён системным ANR System UI в программном эмуляторе без
KVM. Ошибка первого тестового стенда (проверка аниматора после ожидания idle,
когда он уже мог закончиться) исправлена: теперь фаза фиксируется в том же
UI-вызове, что и нажатие. Это не исправление приложения и не скрытое отключение
его проверок. Скриншоты первых прогонов содержали системный диалог; увеличенные
кадры самого View показывают его нативную отрисовку без затемнения диалогом.
В финальном прогоне системный диалог закрыт; получены также чистые скриншоты
всего приложения с видимым дымом в реальном слоте навигации.

Robolectric-сценарии (включая новый случай 0,5×) компилируются; их выполнение
по-прежнему требует разрешения загрузок с `gcp.mirrors.maven.org`.
Отключение анимаций и пересоздание Activity покрыты подготовленными JVM-сценариями,
но не заявляются выполненными на устройстве. Программный эмулятор без KVM не
пригоден для честного заключения о FPS/задержках на телефоне. Профилирование
памяти не выполнялось; отсутствие утечек по результатам профайлера не заявляется.
