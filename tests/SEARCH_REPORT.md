# «Библия»: упрощение интерфейса и оптимизация поиска

## Изменённые файлы

- `app/src/main/java/org/biblememory/app/MainActivity.java` — элементы чтения, debounce, отмена запросов, состояния пустого поиска, обновление виртуального списка, подсветка и восстановление ввода/каталога.
- `app/src/main/java/org/biblememory/app/BibleSearchLogic.java` — кэш обработки стихов, переиспользуемый matcher подсветки, проверки пустого запроса, поиск книги/ссылки через существующий объект Bible.
- `tests/BibleSearchQueryTest.java` — JVM-проверки пустых запросов и сопоставления слов.
- `tests/PickerIntegrationTest.java` — Android-сценарии ввода, очистки, отмены, возврата, отсутствия совпадений, прокрутки и удалённых элементов интерфейса.
- `tests/benchmark_search.py` — воспроизводимая проверка результатов и замеры до/после.
- `tests/search/SearchHarness.java` — шаблон автономного JVM-стенда с настоящими данными и индексом приложения.
- `tests/validation.init.gradle` — исключение автономного стенда из Android unit source set; он запускается отдельным скриптом.
- `tests/SEARCH_REPORT.md`, `tests/README.md` — отчёт и указатель на него.

Схема базы, сохранённые данные, тексты/индекс Библии, коллекции, карточки и учебные алгоритмы не изменялись. Производственных зависимостей не добавлено.

## Интерфейс

Из основного чтения удалены переключатель «Показать/скрыть статусы», его контейнер и заголовок «Текст главы». Статусы и повторения около стихов остаются видимыми, их данные не изменены. Сетка глав основной Библии показывает только название книги без количества глав; размеры и обработчики кнопок сохранены. Подпись в режиме добавления через коллекции не менялась.

Рамка, скругления, размеры, кнопки и цвета поля поиска/результатов сохранены. Поле остаётся прокручиваемым: в каталоге оно находится в ScrollView, в результатах — в заголовке ListView.

## Найденные причины задержек

1. Готовый бинарный индекс и фоновый поиск уже существовали. Однако каждый запрос повторно нормализовал и разбирал тексты всех кандидатов. Например, запрос «и» обрабатывает 23 394 совпадения.
2. Нормализация многократно компилировала регулярное выражение. Подсветка при каждой привязке строки заново разбирала запрос и нормализовала/склоняла каждое слово для каждого поискового терма.
3. На каждый запуск создавался отдельный Thread. Старые ответы отбрасывались по номеру запроса, но сами вычисления продолжались.
4. Debounce отсутствовал; ручной поиск пересоздавал весь экран после каждого результата. Подготовка соседних вкладок также создавала посторонний UI во время поиска.
5. Кэш вкладки мог хранить уже заменённый ScrollView вместо фактически отображаемого ListView, затирая сохранённую позицию каталога.

## Оптимизации

- Один последовательный ExecutorService и debounce 300 мс. Лупа и действие клавиатуры запускают поиск сразу.
- При каждом изменении ввода удаляется отложенный запуск, отменяется предыдущий Future и меняется поколение запроса. Прерывание проверяется поисковым ядром. Ответ применяется только к актуальному поколению, текущему экрану и живой Activity.
- Закрытие экрана отменяет ожидающую работу; при возврате незавершённый актуальный запрос возобновляется. Executor и callbacks освобождаются в onDestroy.
- Нормализованный текст, основы слов и неизменяемые Hit кэшируются лениво по идентификатору стиха. Размер ограничен числом стихов исходного индекса; кэш принадлежит конкретному экземпляру Bible. Кэша неограниченного числа запросов нет.
- Регулярные выражения компилируются один раз. Matcher запроса переиспользуется в списке, а готовая подсветка хранится в LRU на 128 строк.
- Существующая виртуализация ListView и переиспользование строк сохранены. Все результаты доступны через адаптер, без искусственного лимита. При смене запроса старые строки сразу убираются, при ответе меняются данные адаптера и сообщение; поле ввода сохраняет фокус и выделение. Первое переключение между каталогом и результатами сохраняет ввод.
- Не создаётся второе, сразу удаляемое поле поиска при построении списка. Подготовка соседних вкладок откладывается во время поиска.
- Исправлена ссылка на контейнер прокрутки в кэше вкладок: виртуальный список не перезаписывает позицию каталога нулевым смещением.
- Запросы с названием книги/ссылкой, например «Псалтирь», «Пс 118:1–176», «Матфея 5:3–7:29», разбираются и читают тот же Bible. Второй текстовый индекс не создаётся. Проверены полные и сокращённые названия, книги с номером и ошибочные границы.

## Пустой поиск и отсутствие совпадений

Пустая строка, обычные пробелы, табуляция, неразрывные и широкие пробелы считаются пустым запросом. Фоновая задача не создаётся. При первом открытии и повторных пробелах каталог не пересоздаётся ради поиска.

Очистка `×` и удаление последнего символа немедленно отменяют/инвалидируют предыдущую работу и возвращают обычный каталог 66 книг с существующими группами. Позиция каталога сохраняется в прежнем механизме прокрутки. Полный список стихов и сообщение об отсутствии совпадений для пустого запроса не отображаются.

Непустой запрос без результатов показывает ровно «Ничего не найдено», сохраняя текст запроса и доступ к редактированию/очистке. Каталог возвращается после очистки, а не из-за отсутствия совпадений.

## Реально выполненные проверки

- `assembleDebug` — успешно; подпись APK проверена.
- JUnit: **12 тестов прошли**, без ошибок и пропусков (10 проверок существующей модели диапазона и 2 проверки поискового запроса/matcher).
- Автономный JVM-стенд на настоящих `synodal.json` и `synodal.sidx`: для **29 текстовых запросов** совпали полные упорядоченные отпечатки координат и рангов результатов до/после. Для семи измеряемых запросов совпали позиции подсветки. В частности, «и» возвращает все 23 394 совпадения.
- Стенд дополнительно проверил пустой запрос, отсутствие совпадений, прерывание потока, ссылки и диапазоны, полную книгу, сокращённые/нумерованные книги, неверные границы и номер стиха.
- **18 Android-сценариев компилируются**. Их выполнение в этой среде по-прежнему блокирует загрузка зависимости Robolectric: Maven перенаправляет её на `gcp.mirrors.maven.org`, запрещённый текущей сетевой политикой (HTTP 403). Компиляция не означает прохождение UI-сценариев.
- Lint выполнен: остаётся прежняя ошибка `NewApi` в `res/values/styles.xml:5` (API 27 при minSdk 26), 38 предупреждений. Тема приложения в рамках задачи не менялась.
- `git diff --check` — успешно.

## Замеры поискового ядра на сервере

JDK 17, отдельные процессы для исходной и новой версии, настоящие встроенные тексты/индекс. Исходная версия взята из `4b8ae8d`. ## Воспроизведение

Из корня проекта, с JDK 17 и Android SDK 35:

```sh
python3 tests/benchmark_search.py
gradle --no-daemon -I tests/validation.init.gradle -PpickerModelOnly -x :app:createSynodalSearchIndex :app:testDebugUnitTest
gradle --no-daemon -I tests/validation.init.gradle -x :app:createSynodalSearchIndex :app:testDebugUnitTest
gradle --no-daemon -x :app:createSynodalSearchIndex :app:assembleDebug
```

Для скрипта нужны `JAVA_HOME`, `ANDROID_HOME`, Python 3 и доступная локальная история Git до `4b8ae8d`. Он создаёт временные файлы, компилирует настоящее ядро и сравнивает обе версии; исходники и ассеты не переписывает. Исключение `createSynodalSearchIndex` в Gradle использует уже сохранённый `synodal.sidx`.

После разрешения сетевого домена следует выполнить полный Android-набор. На устройстве ещё нужно измерить время появления результатов и кадры прокрутки, проверить клавиатуру/выделение, быстрый ввод/удаление/`×`, возврат из других экранов и восстановление каталога. Старую пользовательскую базу на устройстве в этой среде не проверяли; код её записи не менялся.
