# Навигация и выбор диапазона: проверка обновления

## Изменённые файлы

- `app/src/main/java/org/biblememory/app/MainActivity.java` — отдельный экран «Задать диапазон», выбор границ через общие числовые сетки, системная навигация, восстановление Activity/прокрутки, доступ к сеткам из текста главы.
- `app/src/main/java/org/biblememory/app/PassageSelection.java` — независимые явно заданные границы, без автоматической перестановки.
- `tests/PassageSelectionTest.java` — тесты модели и обхода глав.
- `tests/PickerIntegrationTest.java` — Android-сценарии новой навигации и прежних операций с коллекцией.
- `tests/check_bible_grids.py` — проверка реальных встроенных данных Библии.
- `tests/README.md` — отчёт и команды проверки.

База данных, её версия, схема и миграции не менялись. Сохранение использует уже существующий транзакционный `LocalStore.addPickedPassage`, включая порядок материалов и уникальные карточки. Удаление самостоятельного стиха по-прежнему архивирует учебную запись, сохраняя её идентификатор и историю.

## Реализованная навигация

Обычное добавление: каталог книг → главы → номера стихов → полный текст. Номер открывает текст и временно подсвечивает стих; ничего автоматически не добавляется. Кнопки `+ / − / ✓` обновляются на месте. Из текста доступны сетки «Главы» и «Стихи»; последовательные кнопки перелистывания удалены.

«Задать диапазон» открывает самостоятельный экран с двумя нажимаемыми областями и закреплённой кнопкой «Добавить отрывок». Начало/конец выбираются через те же сетки глав и стихов. Выбор номера фиксирует только редактируемую границу и возвращает к диапазону. Повторное открытие границы использует её прежнюю главу и выделяет прежний стих.

Системный возврат: номера → главы → экран диапазона → исходный текст с быстрыми кнопками и прежней прокруткой. Уход из редактирования без выбора номера не меняет старую границу. Диапазон ограничен одной книгой; противоположная граница не изменяется автоматически. При конце раньше начала видны обе заданные ссылки и ошибка, сохранение недоступно. Совпадающие границы сохраняются как один стих. Корректные диапазоны сохраняются одним элементом коллекции, включая несколько глав.

## Команды

Из корня проекта, с JDK 17, Android SDK 35 и Gradle 8.9:

```sh
python3 tests/check_bible_grids.py
gradle --no-daemon -I tests/validation.init.gradle -PpickerModelOnly -x :app:createSynodalSearchIndex :app:testDebugUnitTest
gradle --no-daemon -I tests/validation.init.gradle -x :app:createSynodalSearchIndex :app:testDebugUnitTest
gradle --no-daemon -x :app:createSynodalSearchIndex :app:assembleDebug
gradle --no-daemon -x :app:createSynodalSearchIndex :app:lintDebug
```

Init-скрипт подключает только тестовые зависимости на время запуска. Производственные зависимости приложения не меняются. Исключение `createSynodalSearchIndex` использует уже включённый в репозиторий `synodal.sidx`, сохраняя отслеживаемый файл без перезаписи.
